# 증미역 공간 지식 그래프 (Jeungmi GeoKG)

서울 지하철 9호선 증미역 반경 1km 안의 건물, 출입구, 필지, 도로, 공공시설, 역, 행정동과 법정동, 환경 센서, 상호(가게)를 "의미 있는 객체"로 쪼개고, 객체마다 공공기관이 매긴 관리번호를 그대로 써서 바뀌지 않는 주소(URI)를 붙인 뒤 GeoSPARQL 1.1 지식 그래프로 엮은 프로토타입입니다.

국토교통부의 "국가기본도 대전환" 방향인 **객체 원자화, 영구 식별자, 자동 갱신, AI 제안 후 사람 승인**을 작은 지역에서 실제 공공데이터로 처음부터 끝까지 돌려 보는 것이 목표입니다.

**URI가 실제로 열립니다:** https://yeodh10.github.io/jeungmi-geokg/ (예: [증미역](https://yeodh10.github.io/jeungmi-geokg/id/station/1150010200106660040000001), [어휘](https://yeodh10.github.io/jeungmi-geokg/def/)). 객체마다 사람이 읽는 페이지와 Turtle(`index.ttl`)이 있습니다.

**지도 앱도 바로 열립니다:** https://yeodh10.github.io/jeungmi-geokg/ 이 지도 앱입니다(옛 주소 `/map/`도 같은 앱을 엽니다). 장소, 주소, 지번, 상호, 공식 번호로 찾고, 누르면 카드에서 층수, 용도, 지은 때와 함께 공식 번호, 출처, 이어진 것을 봅니다. 휴대폰에서도 됩니다. '5분 둘러보기'가 고유 주소, 출처, 이어진 것, 질문, 기계용 원본을 차례로 보여 줍니다. 소개와 그래프 쓰는 법은 [/about/](https://yeodh10.github.io/jeungmi-geokg/about/)에 있습니다.

로컬 서버를 켜면 http://localhost:8000/map 에서 같은 앱에 공개하지 않는 자료 층(공공시설, 도로 구간, 법정동 경계, 국가기본도, 수치지형도), 자유 질문, 기록 탭이 더해집니다([실행](#실행)). 이 화면에는 공개하지 않는 자료가 보이므로 캡처를 바깥에 올리지 않습니다.

## 이 프로젝트로 보여 드리려는 것

공간정보 시맨틱 모델링 업무를 네 가지로 나누고, 각각을 이 저장소의 어디에서 확인할 수 있는지 짝지었습니다.

| 하는 일 | 이 저장소에서 | 바로 보기 |
|---|---|---|
| 여러 공간 자료를 하나의 구조로 설계하고 거버넌스를 세우기 | 12종 공공 자료를 자료 목록(DCAT)으로 묶고, 자료마다 이용 조건과 공개 등급을 적어 SHACL로 강제합니다. 출처, 변경 이력, 공개 경계, 개인정보 규칙은 문서와 검사 코드에 함께 둡니다. | [docs/governance.md](docs/governance.md), [docs/survey-data.md](docs/survey-data.md) |
| 객체 사이 관계를 정의해 지식 그래프 스키마 만들기 | 건물, 출입구, 필지, 도로, 행정구역, 센서, 상호를 GeoSPARQL 객체로 쪼개고 관계(필지 위에 있다, 같은 건물이다, 면한 도로 구간 등)로 잇습니다. 국가기본도 지형지물 분류는 SKOS로 넣었습니다. | [어휘 페이지](https://yeodh10.github.io/jeungmi-geokg/def/), `src/graph/ontology.ttl` |
| AI와 LLM으로 비정형 공간 자료를 구조화하기 | 구청 고시공고 글에서 바뀌는 건물과 필지를 LLM으로 뽑아 변경 제안으로 만들고, 자연어 질문을 GeoSPARQL로 바꿉니다. 키가 없는 공개 사이트의 묻기 탭은 모델 없이 사람이 쓴 질문 틀로 답하고, 틀에 없는 한 장소의 질문은 그 장소의 카드 자료에서 근거를 찾아 답합니다(API 없는 검색 증강). 모델이 지어낸 값이 그래프에 들어가지 않도록 입력 가드와 원문 대조 단계를 둡니다. | `src/llm/`, [docs/llm-eval.md](docs/llm-eval.md) |
| AI 에이전트로 시맨틱 상호운용성을 검증하는 프로토타입 만들기 | Claude Code와 함께 만들었습니다. schema.org, INSPIRE, 위키데이터, BOT 어휘와 잇고, 외부 주소가 실제로 열리는지와 형식을 바꿔도 트리플이 그대로인지를 자동으로 검사합니다. | `src/graph/interop.py`, [docs/interop.md](docs/interop.md) |

지도의 '입체 보기'는 건축물대장의 높이 값으로 건물을 세운 LoD1 모형입니다. 오른쪽 아래 3D 버튼으로 켜고, 마우스로 돌리고 기울이거나 Q와 E 키로 돌리고 R과 F 키로 기울이며, '한 바퀴 돌아보기'로 천천히 돌려 볼 수 있습니다. W, A, S, D와 방향키로 옮기고(두 키를 같이 누르면 대각선, Shift를 누르면 빨리) +와 -로 확대합니다. 지도의 빈 땅을 누르면 Esc처럼 말풍선과 고른 장소를 닫고, 그 자리의 정보는 우클릭이나 길게 누르기로 봅니다. 거리는 어느 한 역에서 미리 재지 않습니다. 카드나 지도 말풍선에서 '거리 기준'으로 고른 곳에서 재고, 목록의 '가까운 순'과 주변 찾기, 조건 찾기도 그곳을 기준으로 합니다.

## 국가기본도 대전환 방향과 이 프로젝트

| 방향 | 이 프로젝트에서 한 것 | 어디에 |
|---|---|---|
| 객체 원자화 | 원천 공공데이터(아래 데이터 표)를 건물, 출입구, 필지, 도로와 도로 구간, 공공시설, 역, 행정동, 법정동, 기초구역 객체로 쪼갰습니다. 출입구는 면한 도로 구간에 이었습니다. 국가기본도 지형지물 분류(수치지도 작성 작업규칙 제9조)를 어휘에 넣고, 국가기본도 건물을 객체ID 그대로 받아 우리 건물과 이었습니다. 모든 객체는 GeoSPARQL Feature이고 모양(Geometry)은 따로 둡니다. 쪼개는 원칙과 파이프라인 단계는 원자화 규칙에 적었습니다. | [docs/uri-policy.md](docs/uri-policy.md), `src/model/`, `src/graph/ontology.ttl` |
| 영구 식별자 | 새 번호를 만들지 않고 건물관리번호, PNU, 도로명코드, 도로구간 일련번호, 법정동코드, 행정동코드, 기초구역번호, 행정표준코드 기관코드를 그대로 URI에 씁니다. 객체가 사라져도 URI는 남기고 상태만 폐지로 바꿉니다. 공개 자료로 만든 URI 페이지를 GitHub Pages에 올려 실제로 열리게 했습니다(배포된 판 약 2만 쪽, 다음 배포 21,872쪽). | [docs/uri-policy.md](docs/uri-policy.md), `src/graph/publish.py` |
| 자동 갱신 | 새 자료가 들어오면 그래프를 덮어쓰지 않고 객체마다 비교해 신규, 변경, 폐지, 주소 연결 제안을 만듭니다. | `src/review/diff_proposals.py` |
| AI 제안 후 사람 승인 | 고시공고 글에서 바뀌는 내용을 뽑는 일만 LLM이 하고, 대상 객체는 코드 규칙으로 찾습니다. 국가기본도 건물의 주소를 이용해 주소 미연결 건물을 건물관리번호가 있는 건물에 잇는 제안과, 점만 있는 건물에 국가기본도 모양을 붙이는 제안도 규칙으로 만듭니다. 모든 제안은 SHACL 검사를 거쳐 승인을 받아야 그래프에 들어가고, 누가 언제 승인했는지는 PROV-O로 남습니다. 국가기본도 규칙 제안 249건은 사람이 Claude에게 검토를 맡겼고, Claude가 데이터에서 잰 기준으로 결정했습니다. 기록의 검토자 이름에도 그대로 남아 있습니다. 다만 컴퓨터를 옮기면서 반려 110건의 기록을 잃었습니다(아래 '한계와 증거 수준' 참고). | `src/llm/`, `src/review/`, `src/graph/shapes.ttl` |

## 표준과 상호운용성

우리 어휘(jgk)를 모르는 시스템도 이 그래프를 읽을 수 있도록, 외부 표준 위에 세우거나 외부 표준과 이었습니다. 외부 주소는 실제로 열리는지(없는 이름이면 404를 주는지) 확인한 것만 씁니다.

| 표준 | 쓰임 | 어디에 |
|---|---|---|
| GeoSPARQL 1.1 (OGC) | 모든 공간 객체와 모양, 위상 함수 | `src/graph/ontology.ttl` |
| SOSA/SSN (W3C, OGC) | 환경 센서와 1시간 관측값 | `src/model/build_sensors.py` |
| QUDT 단위 | 관측값 단위 (℃, %, dB, lux) | 어휘의 관측 항목 |
| PROV-O, SHACL, SKOS | 승인 기록, 데이터 규칙, 국가기본도 지형지물 분류 | `src/review/`, `shapes.ttl` |
| schema.org, INSPIRE 지형지물 개념, 위키데이터 | 외부 어휘의 이름으로 읽기 (증미역은 위키데이터 Q59989와 같은 실물) | [docs/interop.md](docs/interop.md), `src/graph/alignment.ttl` |
| BOT (W3C Linked Building Data) | BIM 모델 건물과 잇기 | [docs/bim.md](docs/bim.md) |

상호운용성 검사(`python -m src.graph.interop`)는 외부 주소 17개가 모두 열리는지, RDFS 추론 뒤 schema.org 이름만으로 역과 주소, 식별자를 찾을 수 있는지, JSON-LD와 N-Triples로 바꿔도 32만여 트리플이 하나도 바뀌지 않는지 확인하고, 증미역 좌표가 위키데이터 좌표와 얼마나 떨어져 있는지(44.8m) 잽니다.

## 시점별 판

승인으로 실제로 바뀐 트리플은 하나하나 RDF 진술(`jgk:hasChange`)로 함께 남깁니다. 정정으로 승인을 철회한 일도 사건으로 남습니다. 그래서 판마다 그래프를 통째로 복사하지 않아도 특정 시각의 값이나 두 시각 사이의 변경을 SPARQL로 조회할 수 있습니다(쿼리 15, 16, `src/graph/editions.py`). 시각 T의 값은 트리플마다 T 이전의 마지막 사건으로 정하며, 쿼리는 객체와 모양 노드마다 한 번씩 돌립니다. 로컬 지도의 기록 탭에서 '승인 바로 전 값과 견주기'를 누르면 그 시점의 값을 되살려 지금 값과 나란히 보여 줍니다. 되살린 값이 승인 전 원천 그래프와 똑같은지는 테스트로 확인합니다.

실제 사례: 강서구 **도로명주소 폐지 고시**(제2026-140호, 2026-10-28)의 첨부 폐지조서 12줄 가운데 범위 안에 있는 4곳을 그래프의 건물 5개와 맞춰, 건물과 출입구를 폐지하는 제안 5건을 만들었습니다(위 검토 화면). 이 5건은 아직 대기 중입니다.

- 원천 그래프는 원본에서 언제든 다시 만들 수 있게 두고, 승인된 변경만 그 위에 승인 순서대로 얹습니다. 지금까지의 결정은 사용자가 위임한 검토자 Claude가 내렸습니다(기록의 검토자 이름에 남아 있습니다).
- 새 자료로 원천 그래프를 다시 만들면 승인 당시의 값이 사라졌을 수 있습니다. 빼려는 값이나 바꿀 객체가 없으면 그 제안은 적용하지 않고 충돌로 남겨 `/api/status`와 검토 화면에 보여 줍니다.
- 공간 관계(맞닿음, 포함, 겹침)는 미리 계산해 두지 않고, SPARQL 안에서 `geof:sfTouches`, `geof:sfIntersects` 같은 GeoSPARQL 위상 함수로 계산합니다.
- LLM은 바뀌는 내용을 뽑거나 질문을 SPARQL로 바꾸는 데만 쓰고, URI를 정하는 일은 맡기지 않습니다. 모델이 영구 식별자를 지어내지 못하게 하려는 것입니다.

## 실행

명령은 프로젝트 폴더에서 Git Bash로 실행하는 것을 기준으로 적었습니다. Windows PowerShell에서는 `.venv/Scripts/python`을 `.\.venv\Scripts\python.exe`로 바꿔 씁니다.

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
cp .env.example .env                                   # ANTHROPIC_API_KEY 등 키 값
```

원본 압축 파일을 `data/raw/_archives/`에 넣고 전체를 다시 만듭니다. 7-Zip이 없으면 먼저 `pip install py7zr`로 설치합니다.

```bash
.venv/Scripts/python -m src.pipeline --unpack
```

범위 자르기, 객체와 URI, 그래프, 예시 쿼리 결과(`data/processed/query_check.md`), SHACL 검사 결과(`validation_report.md`), URI 페이지(`site/`)가 차례로 만들어집니다.

화면 띄우기:

```bash
.venv/Scripts/python -m uvicorn src.review.app:app --host 127.0.0.1 --port 8000
```

http://localhost:8000 에서 변경 제안을 검토하고, http://localhost:8000/map 에서 지도 앱의 로컬 화면을 씁니다. 공개 사이트와 같은 앱(`web/app/`)이고, 자료만 이 서버의 API(`/api/places`, `/api/card` 등)에서 받습니다. 로컬에서만 더해지는 것은 `web/local/`에 있고, 공개 사이트에는 복사하지 않습니다.

- 왼쪽 아래 '로컬 서버, 보류 자료 층': 공공시설 23곳, 도로 구간, 법정동 경계, 국가기본도 건물, 수치지형도 건물을 켜고 끄며 범례를 봅니다. 공개 사이트에 없는 객체의 카드에는 공개 페이지 링크가 없습니다.
- 묻기 탭 위 '자유 질문': 보내기 전에 Claude API 키가 있는지 알려 주고, 키가 없으면 보내지 않습니다. 답에는 AI가 만든 쿼리라고 적습니다.
- 기록 탭: 승인된 변경, 고른 장소의 '승인 바로 전 값과 견주기', 날짜를 골라 시점 비교, 검토 화면으로 가기.
- 검토 화면의 '지도에서 보기'는 이 앱에서 그 장소를 엽니다.

키 없이 자유 질문 화면만 확인하려면 가짜 모델 서버를 씁니다. 모델 호출 함수만 가짜로 바꾸고, `.env`를 읽지 않으며, API 주소를 닿지 않는 곳(`http://127.0.0.1:9`)으로 둡니다. 승인 기록은 언제나 임시 복사본을 씁니다. 사본은 포트마다 한 자리에 두고 켤 때마다 덮어써서 쌓이지 않습니다(복사할 원본은 `--proposals`로 고릅니다).

```bash
.venv/Scripts/python -m tests.serve_fake_llm --port 8000
```

이 서버는 공개 보류 자료까지 그대로 읽는 로컬 전용 화면입니다. 그래서 127.0.0.1에만 띄우고, localhost, 127.0.0.1, [::1] 이외의 이름으로 들어온 요청은 받지 않습니다.

## 주요 기능

### 변경 제안과 승인

- 제안은 출처(`rule-candidate`, `data-diff`, `llm-notice`, `notice-table`)와 상관없이 형식이 같고, 대상 URI, 근거, 넣고 뺄 트리플, 위치를 담습니다.
- 검토 화면은 바뀌는 내용을 객체별로 "현재 → 변경 후"로 보여 주고, 반영 결과를 SHACL로 미리 검사해 규칙을 어기면 승인을 막습니다.
- 승인하면 바뀐 객체가 `prov:wasInfluencedBy`로 제안을 가리키고, 제안에는 승인한 사람과 시각이 남습니다. 반려한 제안도 기록에 남습니다.
- 검토 화면: 같은 고시에서 나온 제안을 묶어 보여 줍니다(예: "서울특별시 강서구 고시 제2026-140호, 이 고시 5건"). 검색, 종류와 출처별 거르기, 정렬을 할 수 있고 결정 이력(누가, 언제, 사유)도 볼 수 있습니다. 반려할 때는 사유를 꼭 적어야 합니다. 단축키(j, k 이동, a 승인, r 반려, / 검색, ? 안내)로도 처리할 수 있습니다.
- 묶어 결정: 같은 고시에서 나온 대기 제안을 순서대로 검사합니다. 각 제안은 앞 제안을 반영한 그래프 위에서 SHACL로 검사합니다. 통과한 제안만 한 번에 승인하고, 규칙을 어긴 제안은 대기로 남깁니다. LLM이 뽑은 제안과 경고(flags)가 붙은 제안은 묶어 승인할 수 없어 하나씩 봐야 합니다. 이렇게 하면 같은 건물을 두 제안이 서로 다르게 바꾸는 경우처럼 하나씩 볼 때는 드러나지 않는 충돌을 잡을 수 있습니다.
- 결정 정정: 승인이나 반려가 틀렸으면 기록을 지우지 않고 정정합니다. 대기로 되돌리거나, 승인을 반려로, 반려를 승인으로 바꿀 수 있으며, 이때도 사유를 꼭 적어야 합니다. 앞의 결정은 정정 이력에 그대로 남습니다. 승인을 철회하면 그 일도 사건으로 남아 지난 이력이 지워지지 않습니다. 뒤에 승인된 제안이 같은 객체를 바꿨거나 가리키면 그 제안부터 정정하도록 막고, 철회한 뒤의 그래프가 규칙을 어기면 철회하지 않습니다.
- 서버를 켜면 그래프를 백그라운드에서 미리 불러 둡니다(`/api/status`로 확인). 자연어 질의의 SPARQL은 별도 프로세스에서 실행합니다. 시간이나 메모리 상한을 넘기면 504를 돌려주고, 그 프로세스를 끝낸 뒤 새로 띄웁니다. 새로 띄우는 동안 들어온 질의에는 503을 돌려줍니다.
- 503을 돌려주는 경우는 세 가지입니다. 질의 작업 프로세스를 새로 띄우는 중일 때, 다른 프로세스가 제안 파일을 잠근 채 기다려도 풀리지 않을 때(파일은 그대로 둠), 제안 파일에 읽을 수 있는 기록이 하나도 없을 때(깨진 파일로 보고 덮어쓰지 않은 채 멈춤)입니다.
- 지도 앱은 공개 사이트와 로컬 서버가 같은 코드를 씁니다. 찾기(장소, 주소, 지번, 상호, 공식 번호), 분류 칩, 결과 목록과 번호 표식, 장소 카드(공식 번호, 출처, 이어진 것, 없는 정보), 주변 찾기, 묻기, 자료 탭, 5분 둘러보기, 지도 보기(건물 종류, 층수, 지은 때, 행정동, 입체 보기)가 있습니다. 고른 장소와 배율이 주소창에 남아 그 주소를 그대로 공유할 수 있습니다.
- 로컬 지도는 여기에 도로 구간, 법정동 경계, 공공시설, 국가기본도와 수치지형도 건물 층, 자유 질문, 기록 탭을 더합니다. 카드의 '장소 페이지 열기'와 '기계용 원본'은 공개 사이트에 그 장소의 페이지가 있을 때만 보입니다.
- API는 URI 입력을 검사해 SPARQL 주입을 막습니다. 제안 파일을 쓸 때는 OS 파일 잠금을 걸어 여러 프로세스의 결정이 섞이지 않게 하고, 지도 레이어는 gzip과 ETag를 붙여 보냅니다. Host와 Origin 헤더를 확인하고, 요청 본문 크기, 질문 수, 무거운 검사의 동시 실행 수에 상한을 둡니다.

### 자동 갱신

| 제안 | 언제 | 승인하면 |
|---|---|---|
| create | 새 자료에만 있는 객체 | 객체와 모양을 추가 |
| update | 값이 달라진 객체 | 이전 값을 빼고 새 값을 넣음 |
| retire | 새 자료에서 사라진 객체 | 지우지 않고 상태를 폐지로, 폐지 확인일 기록 (URI 유지) |
| link | 주소 미연결 건물이 새 건물관리번호 건물의 모양으로 쓰임 | 상태를 주소 연결됨으로, `jgk:sameBuildingAs`로 새 URI와 연결 |

빼는 값은 두 자료를 비교해 얻은 값이 아니라, 승인까지 반영한 현재 그래프에서 뽑습니다. 승인된 값을 덮어쓰게 되면 경고(flags)를 남깁니다.

### 고시공고에서 제안 만들기

- 글로 된 본문에서는 LLM(`claude-opus-5-5`, 구조화 출력)이 변경 종류, 대상의 주소나 이름, 새 값, 원문 문장을 뽑습니다. 안전 분류기가 거절하면 서버가 다른 모델로 다시 돌립니다(`fallbacks: "default"`).
- 첨부가 표(엑셀)이면 LLM 없이 코드가 읽습니다.
- 대상 객체는 코드가 이름, 도로명주소, 지번 순서로 찾습니다. 정확히 하나로 좁혀진 것만 제안이 되고, 후보가 여럿이면 보고서에만 남깁니다.
- 모델의 출력은 코드가 다시 확인합니다. 근거 문장, 대상 주소와 이름, 새 값이 원문에 있어야 제안이 되며, 고시 묶음과 고시 객체는 모델 출력이 아니라 파일 머리에 적힌 시군구와 번호로 정합니다.

### 입력 가드

- 고시 본문과 자연어 질문은 LLM에 보내기 전에 입력 가드(`src/guard`)를 거칩니다. 판정이 차단이면 보내지 않고, 검토이면 제안에 경고를 남깁니다. 가드는 세 층으로 되어 있습니다.
  - 규칙 층: 숨은 문자, 유사 문자, 인코딩을 풀어 여러 사본(뷰)을 만든 뒤 정규식을 적용합니다. 표준 라이브러리만 쓰고, 어떤 입력이든 CPU 시간 2초 안에 끝나도록 제한했습니다.
  - LLM 층(고시만): 원문을 호출마다 바뀌는 난수 구분자로 감싼 뒤 작은 모델(`claude-haiku-5-5`)이 읽고, 돌려 말한 지시를 가려냅니다. 이 층이 판정을 내리지 못하면 통과시키지 않고 검토로 넘깁니다.
  - 출력 층: 모델이 뽑은 글에서 전화번호, 이메일, 비밀값을 가립니다.
- 규칙 층 측정 결과(이미 본 묶음이라 블라인드 평가는 아닙니다): 공격 92줄 중 차단 28, 검토 3. 일부러 만든 우회 89줄 중 차단 82, 검토 2. 실제 고시 97건(평가용 95건과 사례 고시 2건)과 질문 25개에서는 오탐이 0건입니다. LLM 층은 유료 호출이라 실제 모델로는 재지 않았습니다.
- 입력 가드로 모든 공격을 막지는 못합니다. 위조 사실, 업무 문체로 쓴 작성 지시, 바꿔 말하기, 권위 사칭은 행정 문서와 겉모양이 같아서 걸러 내지 못합니다. 그래서 뒤 단계를 허용 목록 방식으로 묶었습니다. 고시는 코드가 객체를 찾고, 근거 문장, 주소, 새 값, 효력 날짜를 원문과 대조합니다. 주소는 자료에 있는 낱말로만 풀고, 사람 승인을 거쳐야 그래프에 들어갑니다. 질의는 읽기 쿼리만 실행합니다.

### 키 없는 질문 (공개 사이트 묻기 탭)

- 공개 사이트에는 서버도 API 키도 없어서, 묻기 탭의 입력칸은 모델 없이 브라우저 안에서 답합니다. 질문 틀은 `config/questions.yaml`의 사람이 쓴 쿼리 17개이고, 틀마다 같은 뜻의 다른 말투(forms)를 적어 두었습니다.
- 틀에는 빈칸이 있습니다(거리, 지상 층수, 용도, 법정동, 길 이름, 업종, 이름 낱말, 사용승인 연도, 출입구 수, 세대수). 빈칸이 받을 수 있는 값은 그래프에서 세어 정하고(`src/graph/askforms.py`), 빌드 때 모든 조합(3,429가지)마다 그 쿼리를 공개 범위 그래프에서 실행해 `ask.json`에 담습니다.
- 브라우저(`web/app/ask-match.js`)는 입력에서 빈칸 값을 단위와 사전으로 찾고, 두 글자 조각 유사도로 가장 가까운 말투를 고른 뒤, 그 조합의 결과를 보여 줍니다. 여러 틀에 두루 나오는 조각('증미', '건물')은 가볍게 셉니다.
- 짐작하지 않습니다. 유사도가 낮으면 못 알아들었다고 하고 비슷한 질문을 보여 줍니다. 틀이 받지 않는 조건이나 반대 비교('10층 이하'), 미리 실행하지 않은 값('350m')이 있으면 답하지 않고 고를 수 있는 값을 알려 줍니다. '15층 넘는'처럼 정확히 바꿀 수 있는 말은 '16층 이상'으로 바꾸고, 그렇게 바꿨다고 답 아래에 적습니다.
- 답 아래 '어떻게 찾았나요'에 고른 틀, 가장 가까운 말투, 유사도, 빈칸 값, 실행한 쿼리를 보여 줍니다. 로컬 서버에서는 이 입력칸 대신 Claude 자유 질문을 씁니다.
- 틀은 증미역 둘레나 전체 건물을 묻는 것이라, '강서아이티밸리 몇 층이야', '올리브영 증미역점 주소', '증미역에서 가양역까지 거리', '가양역 500m 주변 카페'처럼 한 장소를 물으면 그래프에서 찾아 답합니다(`web/app/ask-rag.js`). 모델과 API 없이 하는 검색 증강 답하기입니다.
  - 찾기: 찾기 색인으로 질문 속 장소를 찾고(최대 둘, 초성과 한영 오타도 받음), 무엇을 묻는지(층수, 사용승인일, 용도, 주소, 지번, 공식 번호, 노선, 옆 역, 행정동, 우편구역, 길, 입구, 들어 있는 건물, 출처, 거리, 둘레의 업종)를 낱말 목록으로 정합니다.
  - 근거: 그 장소의 카드 자료(공개 범위 그래프에서 빌드 때 만든 `card.json`)에서 칸을 고릅니다. 역이나 상호의 카드에 없는 칸은 이어진 역사 건물이나 들어 있는 건물의 카드에서 찾고 그렇다고 적습니다. 거리는 두 곳의 좌표로 잰 직선 거리입니다.
  - 답: 사람이 쓴 문장 틀에 근거 값을 넣고, 근거 칸 목록과 '어떻게 찾았나요'를 함께 보여 줍니다. 값이 없으면 지어내지 않고 없다고 답하고, 영업시간이나 전화번호처럼 이 자료에 아예 없는 것은 없는 정보라고 답합니다. 장소를 찾지 못하면 답하지 않습니다.
  - 종류 묻기: '증미역에서 가장 가까운 닭한마리 집', '국밥집 어디 있어', '가양역 1km 이내 쌀국수'처럼 가게나 시설의 종류를 물으면, 찾기 색인 전체에서 상호 이름, 업종, 건물과 단지 이름, 바로가기 묶음으로 맞는 곳을 모두 모아 기준 장소에서 가까운 차례로 답합니다. 비슷한 말('맛집'은 음식점, '커피숍'은 카페)과 상표 철자('GS25'와 '지에스25', 'CU'와 '씨유')를 함께 찾습니다.
  - 건물 안과 둘레: '강서아이티밸리 안 카페', '강서아이티밸리에 뭐 있어'는 그 건물에 이어진 상호를 층과 함께 답합니다. 한 건물이 건물 정보와 주소 정보에 따로 잡힌 곳이 있어 같은 필지에 선 건물을 함께 봅니다. '등촌역 근처에 뭐 있어'는 반경 300m 안의 상호를 업종별로 셉니다.
  - 순위: '가장 높은 건물', '제일 오래된 건물', '세대수 가장 많은 아파트', '증미역 근처 가장 높은 건물'은 건물 행의 높이, 층수, 사용승인일, 세대수로 줄을 세워 답하고, 값이 있는 건물 몇 곳만 견줬는지 함께 적습니다. 같은 단지의 여러 동은 하나만 보여 줍니다.
  - 있는 곳을 없다고 하지 않습니다. 이름이나 업종에 그 말이 없는 음식은 이어 둔 업종('짜장면'은 중국집, '국밥'은 국/탕/찌개류)의 가게를 따로 보여 주되, 메뉴는 자료에 없어 그 음식을 파는지는 알 수 없다고 적습니다. 은행이나 관공서처럼 상가정보에 아예 없는 갈래는 없다고 하지 않고 이 자료로는 알 수 없다고 답합니다. 정말 없으면 무엇을 어디까지 찾아봤는지 밝히고, 글자가 비슷한 이름이 있으면 함께 알려 줍니다.
  - 장소와 묻는 것이 분명하면 틀보다 먼저 답합니다. 틀은 다른 장소의 층수나 주소를 물어도 증미역 틀에 걸릴 수 있고, 모르는 업종은 기본값('카페')으로 채우기 때문입니다. 그래서 다른 장소를 기준으로 묻거나, 틀의 빈칸 값에 물은 종류가 들어 있지 않으면 틀에 맡기지 않습니다. 길과 동네를 묻는 질문, 증미역 둘레에서 틀이 아는 업종은 틀이 표와 쿼리까지 보여 주므로 틀에 맡깁니다.

### 자연어 질의

- LLM이 어휘, 그래프의 주요 이름과 값, 예시 쿼리(`src/graph/queries/`)를 보고 SPARQL을 씁니다.
- 실행 전에 코드가 읽기 쿼리(SELECT, ASK)만 통과시키고, 결과는 500행으로 제한합니다. 실행에 실패하면 오류 메시지를 붙여 한 번 더 쓰게 합니다.
- pyoxigraph에는 거리 함수가 없습니다. 그래서 "역에서 300m 안" 같은 조건은 LLM이 `{{NEAR:<URI>:<미터>}}`로 쓰게 하고, 코드가 이를 원 모양(EPSG:5186에서 계산)으로 바꿉니다.

### 센서와 관측 (SOSA/SSN)

- 서울시 도시데이터 센서(S-DoT) 설치 위치정보에서 증미역 1km 안에 있는 5대를 골라(내려받은 주에 관측이 있는 것은 4대), 모델 시리얼을 그대로 써서 `sensor/{시리얼}` URI를 붙였습니다. 관측 URI는 `observation/{시리얼}-{측정 시각}-{항목}`입니다.
- 센서는 설치 주소와 도로명주소가 같은 건물에 `jgk:addressBuilding`으로 잇습니다. 다만 센서 위치가 그 건물에서 8.8~24.1m 떨어져 있어(가로등이나 전봇대에 단 것으로 보임) '건물에 달렸다'(`sosa:isHostedBy`)고는 쓰지 않았습니다.
- 공개 사이트의 센서 페이지는 항목별 개수, 평균, 범위와 시간별 꺾은선 차트를 보여 줍니다. 쿼리 14는 증미역 500m 안 센서의 평균 소음과 기온을 그래프에서 구하고, 그 값이 원본 CSV로 직접 계산한 값과 같은지 테스트로 확인합니다.

### BIM 연결

- BIM은 그래프에 합치지 않고, 같은 건물이라는 연결(`jgk:bimBuilding`)만 둡니다. 층, 공간, 부재는 IFC를 W3C BOT 어휘로 바꾼 BIM 그래프에 그대로 둡니다.
- 건물관리번호가 같으면 번호로 잇고, 번호가 없으면 위치 점을 품은 건물 모양이 하나뿐일 때만 위치로 잇습니다. 층수는 건축물대장과 비교해 근거에 적고, 검토자가 승인합니다.
- 범위 안 건물의 공개 IFC를 찾지 못해, 규칙은 테스트에서 만든 작은 BOT 그래프로만 확인했습니다([docs/bim.md](docs/bim.md)).

### 데이터 규칙 (SHACL)

`src/graph/shapes.ttl`에 적은 규칙은 상태 값, 출처, 기본 모양, 건물 식별 번호(건물관리번호 25자리와 GIS 번호 28자리 중 정확히 하나), PNU 형식, 기관코드 7자리, 폐지하면 폐지 확인일, 출입구는 건물과 이어질 것, 같은 건물 잇기의 대상(있는 건물, 자기 자신과 사슬 금지, 하나씩), 고시의 표제와 고시일은 하나씩, 관측은 센서, 항목, 값, 시각이 하나씩일 것 등입니다. WKT 값 검사, 종류와 모양 출처 빼기 금지처럼 SHACL로 적을 수 없는 규칙은 `src/graph/validate.py`에 있습니다. 첫 검사에서 필지 1,697개에 출처가 빠진 것을 찾아 고쳤습니다.

## 기술 스택

Python 3.12, geopandas, shapely, pyproj, pyogrio, rdflib, pyoxigraph (SPARQL, GeoSPARQL 위상 함수), pyshacl, owlrl (RDFS 추론), Claude API, FastAPI, MapLibre GL JS(저장소에 둠), OpenFreeMap 벡터 타일을 구워 저장소에 둔 배경지도(OpenStreetMap 자료). 저장 좌표계는 EPSG:4326, 거리 계산은 EPSG:5186입니다. 기본값을 바꾸거나 새로 정한 사항은 [docs/decisions.md](docs/decisions.md)에 날짜와 이유를 함께 적었습니다.

## 만든 방법

이 저장소는 AI 코딩 에이전트(Claude Code)와 함께 만들었습니다. 사람이 목표, 규칙, 자료와 이용 조건, 승인 여부를 정하고, 에이전트가 구현과 검증을 맡았습니다.

- **규칙을 먼저 정함**: 값과 좌표는 추측하지 않는다, 공식 번호를 URI에 그대로 쓴다, 원본과 키는 커밋하지 않는다, 이용 조건을 확인하지 못한 자료는 공개하지 않는다. 에이전트는 이 규칙 안에서 일했고, 규칙과 부딪히는 선택은 근거와 함께 [docs/decisions.md](docs/decisions.md)에 남겼습니다.
- **확인한 것만 씀**: 외부 어휘 주소는 실제로 열어 확인했고, 없는 이름에도 200을 돌려주는 주소(OGC CityGML 3.0)는 쓰지 않았습니다. 센서 평균, 위키데이터 좌표 같은 숫자는 원본으로 따로 계산한 값과 비교해 맞췄습니다.
- **여러 에이전트로 감사**: 화면과 API를 고칠 때는 감사, 구현, 검증 역할을 나눈 워크플로로 작업했습니다(커밋 790ce20).
- **테스트로 묶음**: 기능마다 흐름 테스트를 두었고, 실제 승인 기록을 건드리지 않도록 임시 복사본으로만 시험합니다.
