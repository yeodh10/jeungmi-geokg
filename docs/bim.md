# BIM 연결 설계: 건물 하나의 BIM 모델을 공간 지식 그래프에 잇기

공간 지식 그래프의 건물은 지도 위 객체(모양, 주소, 필지, 도로와의 관계)다. BIM은 같은 건물의 속(층, 공간, 벽, 설비)이다. 둘을 하나로 합치지 않고, **같은 건물이라는 연결만 그래프에 두고** 속은 BIM 쪽에 그대로 둔다. 이 문서는 그 연결을 어떻게 만들고 검증하는지 적는다.

- 프로토타입: [src/review/bim_proposals.py](../src/review/bim_proposals.py) (BOT Turtle을 받아 연결 제안을 만든다)
- 테스트: `python -m tests.test_bim_link`
- 어휘: `jgk:bimBuilding`(우리 건물에서 BIM 모델 건물로), `jgk:Building rdfs:subClassOf bot:Building`([alignment.ttl](../src/graph/alignment.ttl))

## 지금 상황

- **증미역 1km 안 건물의 공개 IFC 파일은 찾지 못했다.** 그래서 실제 BIM으로 돌린 결과는 없다. 연결 규칙과 코드는 테스트에서 만든 작은 BOT 그래프로만 확인했다(테스트 파일 머리에 '실제 BIM 자료가 아니다'라고 적었다).
- 국토교통부는 2022년 7월 「스마트 건설 활성화 방안」에서 신규 공공사업에 BIM을 단계적으로 의무 적용한다고 했다. 2022년 하반기 1,000억 원 이상 도로 공사부터 시작해 2023년 철도와 건축, 2024년 하천과 항만으로 넓히고, 2026년 500억 원, 2028년 300억 원 이상으로 대상 공사비를 낮춘다([머니투데이방송, 2022-07-20](https://news.mtn.co.kr/news-detail/2022071914311449106)). 앞으로 공공 건물부터 BIM 납품물이 쌓인다는 뜻이다. 그 BIM을 국가기본도 객체와 잇는 규칙이 미리 있어야 한다.

## 표준

| 단계 | 표준 | 쓰임 |
|---|---|---|
| BIM 원본 | IFC (ISO 16739-1) | 설계, 시공 납품물. 건물(IfcBuilding), 층(IfcBuildingStorey), 공간(IfcSpace), 부재 |
| 위치 맞추기 | IFC4 IfcMapConversion, IfcProjectedCRS | BIM 로컬 좌표를 EPSG:5186 같은 지도 좌표로. 없으면 IfcSite의 기준 위경도 |
| 그래프로 바꾸기 | BOT (W3C Linked Building Data 그룹, `https://w3id.org/bot#`) | 건물, 층, 공간, 부재의 위상만 담는 작은 어휘. IFCtoLBD 같은 변환기가 IFC를 BOT Turtle로 바꾼다 |
| 우리 그래프 | GeoSPARQL 1.1 + jgk | 건물은 `jgk:Building`이자 `bot:Building`. BIM 모델 건물과는 `jgk:bimBuilding`으로 잇는다 |

BOT의 이름(Building, Storey, Space, Element, hasStorey 등)은 BOT 문서를 받아 정의가 있는 것을 확인했다(`python -m src.graph.interop`). ifcOWL 주소는 2026-10-30에 403을 돌려줘서 확인할 수 없어 쓰지 않았다.

## 무엇을 어디에 두나

| 내용 | 둘 곳 | 까닭 |
|---|---|---|
| 건물이 어디 있고 어느 필지, 도로, 동과 이어지나 | 공간 지식 그래프 | 국가기본도 객체의 역할 |
| 층, 공간, 벽, 설비 | BIM 그래프 (BOT) | 양이 많고 바뀌는 주기가 다르다. 시설 관리자가 고친다 |
| 같은 건물이라는 연결 | 공간 지식 그래프 (`jgk:bimBuilding`) | 사람이 승인한 연결만 넣는다 |
| 층 수 같은 요약 | 둘 다 (견주기만) | 대장 값과 BIM 값이 다르면 검토 근거가 된다 |

두 그래프는 URI로만 이어진다. 그래서 BIM 모델이 새 판으로 바뀌어도 우리 그래프는 연결 하나만 고치면 된다. 반대로 우리 건물이 폐지돼도 BIM 그래프는 그대로 남는다.

## 잇는 규칙 (src/review/bim_proposals.py)

1. **번호로**: BIM 건물에 건물관리번호(IfcBuilding 속성 세트에 적은 값)가 있고 그래프에 같은 번호 건물이 있으면 잇는다. BIM 위치 점도 있으면 그 건물 모양에서 30m 안인지 함께 본다. 넘으면 '확인 필요'로 적는다. 지하 역사처럼 모양이 점뿐인 건물이 있어서 거리를 넉넉히 둔다.
2. **위치로**: 번호가 없으면 위치 점을 품은 그래프 건물 모양이 꼭 하나일 때만 잇는다. 근거에 '위치로만 찾았다(확인 필요)'를 적는다.
3. **잇지 않음**: 번호가 그래프에 없거나, 위치가 없거나, 위치 점을 품은 모양이 없거나 여럿이면 제안하지 않고 까닭을 남긴다.
4. **층 수 견주기**: BOT 층 이름이 B로 시작하면 지하층으로 센다. BIM의 지상, 지하 층 수를 대장 값과 견줘 근거에 적는다. 다르면 '확인 필요'다.

연결은 다른 변경처럼 **제안을 거쳐 사람이 승인해야** 그래프에 들어간다. 승인 기록은 PROV-O로 남고, 바꾼 트리플은 시점별 판 기록(`jgk:hasChange`)으로 남는다.

## 시험 결과 (테스트용 BOT 그래프)

| 시험 건물 | 넣은 값 | 결과 |
|---|---|---|
| A | 증미역 역사 건물관리번호, 위치, 층 B1~B3 | 번호로 이음. 층 수 BIM 지상 0, 지하 3과 대장 지상 0, 지하 3이 같음 |
| B | 번호 없음, 어느 건물 모양 안의 점, 층 1F와 2F | 위치로 이음, '확인 필요' |
| C | 번호 없음, 부산 좌표 | 잇지 않음 (품은 모양 0개) |
| D | 그래프에 없는 번호 | 잇지 않음 |

A와 B의 제안은 SHACL 검사를 통과했다. 시험 복사본에서 A를 승인하면 역사 건물에서 BIM 건물로 `jgk:bimBuilding`이 생긴다.

## 실제 BIM이 생기면 할 일

1. IFC를 받아 IfcMapConversion이 있는지 본다. 없으면 IfcSite 기준점을 쓰고, 둘 다 없으면 위치로 잇지 않는다.
2. IFCtoLBD로 BOT Turtle을 만든다. 건물관리번호를 IfcBuilding 속성 세트에 적어 달라고 납품 기준에 넣는 것이 가장 확실하다.
3. `python -m src.review.bim_proposals <BOT 파일>`로 제안을 만들고 검토 화면에서 승인한다.
4. 층 수가 다른 건물은 대장과 BIM 중 무엇이 맞는지 따로 확인한다.
