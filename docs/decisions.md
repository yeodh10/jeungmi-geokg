# 결정 기록

기본 기술 스택에서 바꾸거나 새로 정한 것만 날짜와 함께 한두 줄로 적는다.

- 2026-10-28 Python은 3.11 이상이라는 조건에 맞춰 3.12로 개발한다.
- 2026-10-28 범위 중심은 내비게이션용DB의 "증미역 9호선" 건물중심점으로 정했다. 역 출입구가 여러 개라서 한 점을 골라야 한다면, 공식 데이터에 있는 역사 건물 중심이 가장 덜 자의적이다.
- 2026-10-28 건물 폴리곤은 범위에 일부만 걸쳐도 포함한다(intersects). 점 자료는 완전히 안에 있을 때만 포함한다(within).
- 2026-10-28 SHP 읽기는 fiona 대신 pyogrio를 쓴다. geopandas 1.x의 기본 엔진이고, 범위(bbox)를 지정해 읽을 때 빠르다.
- 2026-10-28 잘라낸 결과는 GeoPackage 하나(`data/processed/jeungmi_area.gpkg`)에 레이어로 나눠 담는다. 파일 수를 늘리지 않기 위해서다.
- 2026-10-28 `data/processed/`도 당분간 커밋하지 않는다. 민원행정기관 전자지도와 도로명주소 전자지도의 이용 조건을 확인한 뒤 다시 정한다.
- 2026-10-28 GIS건물통합정보와 내비게이션용DB는 공공데이터포털 메타데이터의 "이용허락범위 제한 없음"을 근거로 그대로 쓴다. 링크는 docs/data-sources.md에 있다.
- 2026-10-28 (2026-11-03에 바뀜: 연속지적도 경계를 붙였다) 이번에는 필지를 모양 없이 PNU만 가진 객체로 둔다. 연속지적도는 나중에 붙인다.
- 2026-10-28 건물관리번호를 못 붙인 GIS 건물은 GIS건물통합식별번호(A1)로 `building-gis/` URI를 따로 만들고 "주소 미연결"로 표시한다. 자세한 규칙은 docs/uri-policy.md에 있다.
- 2026-10-28 건물 상세 속성은 GIS건물통합정보 안의 대장 속성을 쓴다. 건축물대장 총괄표제부는 대지 단위 자료라서 필지 객체에 단지 정보를 붙이는 데만 쓴다.
- 2026-10-28 도로명주소 한글(주소DB)은 보류한다. 받아 둔 파일은 쓰지 않는다.
- 2026-10-28 공간 관계는 미리 계산해 넣지 않고 SPARQL의 `geof:sf*` 함수로 그때그때 계산한다. pyoxigraph 0.5.13에서 sfIntersects, sfTouches, sfOverlaps, sfContains, sfWithin, sfDisjoint, sfEquals, sfCrosses가 맞게 동작하는 것을 확인했다. `geof:distance`와 `geof:buffer`는 지원하지 않는다. 그래서 거리 조건은 파이썬에서 따로 계산해야 한다.
- 2026-10-28 어휘 이름공간은 `https://yeodh10.github.io/jeungmi-geokg/def#`(접두어 `jgk:`)로 한다. 객체 URI(`/id/`)와는 경로를 나눈다.
- 2026-10-28 원본 압축 파일과 건축물대장 CSV를 `data/raw/_archives/`에 모으고 `src/ingest/unpack.py`로 푼다. 다른 컴퓨터에서도 같은 상태를 재현하기 위해서다.
- 2026-10-28 pandas는 3.0.3, pyogrio는 0.12.1로 한 단계 낮춘다. 두 번째 개발 컴퓨터(Windows 11, 스마트 앱 컨트롤 켜짐)에서 pandas 3.1.0의 `index`, `nattype` 모듈과 pyogrio 0.13.0의 `Lerc` DLL이 평판 부족으로 차단됐다. 낮춘 버전은 차단되지 않으며, geopandas 1.2.0과 함께 써도 GeoPackage를 읽고 쓸 수 있다.
- 2026-10-29 GIS 폴리곤이 없는 주소 연결 건물(반경 안 324개)은 대장 속성이 없어서 내비게이션용DB의 용도와 층수로 대신 채운다. 필지 PNU는 내비 지번의 대표지번으로 만든다. 대표지번도 없는 168개는 필지에 잇지 않는다.
- 2026-10-29 A1 중복을 판단할 때 모양은 정규화한 뒤 비교한다. 같은 모양이어도 꼭짓점 시작 위치가 다르면, 그대로 비교했을 때 다르다고 나왔다.
- 2026-10-29 객체에는 자기 종류(jgk:Building 등)와 geo:Feature를 둘 다 붙인다. 추론하지 않아도 GeoSPARQL 도구가 Feature로 찾을 수 있게 하려는 것이다.
- 2026-10-29 출입구와 행정동은 docs/uri-policy.md의 초안 규칙대로 그래프에 넣었다. 아직 결과물을 공개하기 전이라 규칙을 확정하면서 바꿀 수 있다.
- 2026-10-29 프로젝트 목표(국가기본도 대전환의 객체 원자화, 영구 식별자, 자동 갱신, AI 제안 후 사람 승인)를 설계 판단의 기준으로 삼는다. 식별자로는 나라에서 쓰는 관리번호를 그대로 쓴다.
- 2026-10-29 역 URI는 역사 건물의 건물관리번호를 그대로 쓴다. 역사 건물은 `config/area.yaml`의 `stations`에 적는다.
- 2026-10-29 공공시설 URI는 행정표준코드 기관코드(7자리)를 쓴다. 같은 건물에 기관이 여럿 있어 건물관리번호로는 구분할 수 없다. 기관코드에는 현존, 폐지 구분이 있어 폐지 상태 규칙과도 맞는다. 우편취급국처럼 기관코드가 없는 곳은 URI를 만들지 않는다.
- 2026-10-29 행정동 URI 규칙을 확정한다. 행정동코드가 공식 번호라 다른 선택지가 없다.
- 2026-10-29 공공시설 이름 맞추기는 정해진 세 규칙으로만 하고, 맞지 않는 곳은 사람이 정하도록 검토 목록에 남긴다. 고용복지플러스센터와 고용센터처럼 이름이 다른 경우를 기계가 같다고 단정하지 않기 위해서다. 기계가 후보를 내고 사람이 승인하는 이 흐름은 3주차 변경 제안 단계와 같은 방식이다.
- 2026-10-29 변경 제안은 출처(규칙 후보, 데이터 갱신 비교, LLM 문서 추출)와 상관없이 한 형식으로 만든다. 승인된 제안만 승인 순서대로 원천 그래프 위에 SPARQL UPDATE로 얹는다. 원천 그래프를 건드리지 않아야 원본에서 언제든 다시 만들 수 있다. 승인 기록은 PROV-O(`prov:wasInfluencedBy`)로 남긴다.
- 2026-10-29 제안 기록은 데이터베이스 없이 JSON 파일 하나(`data/processed/review/proposals.json`)에 둔다. 시연 규모에서는 이것으로 충분하고, 파일이 하나라 옮기거나 되돌리기 쉽다.
- 2026-10-29 검토 화면 지도는 배경지도 없이 그래프에서 조회한 건물 모양만 그린다. 외부 지도 서비스 키 없이 돌아가고, 화면에 보이는 것이 모두 그래프 내용이다.
- 2026-10-29 (위 결정을 바꿈) 배경지도가 없으니 길과 지명이 보이지 않아 위치를 알아볼 수 없었다. 채도를 낮춘 OpenStreetMap 타일을 깔고, 그래프의 건물은 파란색 계열로 그려 배경지도의 회색 건물과 구분한다. 배경지도는 지도 화면에서 끌 수 있다. 키를 받으면 브이월드 배경지도로 바꿀 수 있다.
- 2026-10-29 FastAPI 테스트 도구를 쓰려고 httpx 0.28.1을 requirements에 넣는다.
- 2026-10-29 자동 갱신은 새 자료로 만든 그래프로 지금 그래프를 덮어쓰지 않는다. 새 자료의 그래프와 지금 그래프를 객체(자신과 모양 노드의 트리플)마다 비교해 그 결과를 제안으로 만든다. 갱신도 사람이 승인해야 반영된다는 원칙을 지키기 위해서다. 실제 새 자료가 오기 전까지는 지금 자료를 일부러 바꾼 시험용 자료로 확인한다(tests/test_diff.py).
- 2026-10-29 고시공고 처리에서 LLM은 변경 내용을 뽑는 데만 쓰고, 객체를 찾는 일은 코드 규칙으로 한다. LLM이 URI를 지어내면 영구 식별자 원칙이 깨지기 때문이다. 뽑은 결과의 형식은 구조화 출력(Pydantic 스키마)으로 검증한다.
- 2026-10-29 자연어 질의는 LLM이 SPARQL을 쓰면 코드가 검사한 뒤 실행한다. 거리 조건은 코드가 자리표시(`{{NEAR:URI:미터}}`)를 원 모양으로 바꿔 처리한다. pyoxigraph에 거리 함수가 없기 때문이다.
- 2026-10-29 LLM은 `claude-opus-5-5`를 쓰고, 안전 분류기가 거절할 때에 대비해 서버 쪽 대체 모델(`fallbacks: "default"`)을 켠다. 시스템 프롬프트는 캐시한다.
- 2026-10-29 URI는 GitHub Pages 정적 페이지로 열리게 한다. 내용 협상(같은 URI로 HTML과 Turtle을 골라 주기)은 정적 호스팅에서는 할 수 없다. 그래서 같은 폴더에 `index.html`과 `index.ttl`을 두고, HTML에서 `rel="alternate"`로 Turtle을 가리킨다.
- 2026-10-29 앱 고도화는 감사 4갈래(검토 화면, 지도 화면, 백엔드, 버그)에서 나온 46건을 모아 우선순위를 정한 뒤, 파일이 겹치지 않게 세 갈래로 나눠 고쳤다. 기존 API 응답 필드는 지우지 않고 더하기만 했다. 반려할 때는 사유를 받게 했다. 반려 기록이 나중에 근거 자료로 쓰이기 때문이다. 묶어 승인하기와 결정 되돌리기는 정정 기록을 어떻게 남길지 먼저 정해야 해서 미뤘다.
- 2026-10-29 `/api/feature?uri=`처럼 사용자 입력을 SPARQL에 넣던 곳은 URI 형식을 검사한 뒤 pyoxigraph의 패턴 조회를 쓰도록 바꿨다. pyoxigraph가 SERVICE로 바깥에 HTTP 요청을 실제로 보내는 것을 확인했다. 그래서 자연어 질의 검사에서도 주석과 작은따옴표를 이용한 우회까지 막는다.
- 2026-10-29 URI 페이지는 `gh-pages` 브랜치에 올려 GitHub Pages로 공개했다. 빌드에는 원본이 필요한데 원본은 커밋하지 않으므로 GitHub Actions에서 빌드를 돌릴 수 없다. 그래서 로컬에서 만든 결과만 올린다. `main` 브랜치의 `data/processed/` 커밋 금지는 그대로다. 공개 전에 건물 이름 가운데 개인을 짐작할 수 있는 것이 있는지 살펴봤지만 찾지 못했다(이름 있는 건물 1,530개).
- 2026-10-29 공개 페이지에서는 이용 조건을 확인 중인 출처의 객체를 통째로 빼고(`publish.hold_sources`), 다른 객체에서 그 객체로 가는 연결도 뺀다. 지금은 민원행정기관 전자지도에서 온 공공시설 23곳이 빠진다.
- 2026-10-29 데이터 규칙은 SHACL(`src/graph/shapes.ttl`)로 적고 pyshacl 0.40.2로 검사한다. 어휘(ontology.ttl)는 무엇이 있는지를, 규칙(shapes.ttl)은 무엇이 맞는지를 나눠 맡는다. 전체 검사는 70초쯤 걸리므로, 승인 전에는 제안 대상 객체 둘레만 떼어 검사한다.
- 2026-10-29 SHACL 첫 검사에서 출처가 없는 필지 1,697개를 찾았다. 총괄표제부가 있는 필지에만 출처를 달았기 때문이다. 이제 필지마다 PNU를 얻은 자료(GIS, 내비 지번, 총괄표제부)를 모두 출처로 단다.
- 2026-10-29 고시 첨부가 표이면 LLM을 쓰지 않고 코드가 읽는다(제안 출처 `notice-table`). 글로 된 본문만 LLM이 맡는다. 구조가 정해진 자료를 LLM에 맡기면 얻는 것 없이 틀릴 위험만 생긴다.
- 2026-10-29 도로명주소 폐지는 그 주소를 쓰는 건물 전부에 해당한다. 그래서 도로명주소로 찾은 건물 묶음과 지번으로 찾은 건물 묶음이 똑같을 때, 그 건물을 모두 폐지로 제안한다. 건물이 철거되면 출입구도 없어지므로 같은 제안에 출입구 폐지를 함께 넣는다.
- 2026-10-29 공공시설과 건물은 도로명주소로 잇고, 단지처럼 한 주소에 건물이 여럿이면 시설 위치를 품은 건물만 잇는다. 처음에는 주소만으로 이었더니 지구대 하나가 아파트 단지 건물 7개에 이어졌다.
- 2026-10-29 묶어 승인할 때는 묶음의 대기 제안을 제안 파일 순서대로 검사하되, 다음 제안은 앞 제안을 반영한 그래프 사본에서 검사한다. 통과한 제안만 사본에 얹고 승인한다. 제안마다 따로 검사하면, 각각은 통과해도 함께 반영하면 규칙을 어기는 경우(같은 건물을 하나는 폐지, 하나는 사용으로 두는 경우)를 놓치기 때문이다. 묶음의 결정은 한 번에 저장하며, 하나라도 저장할 수 없으면 아무것도 바꾸지 않는다. 다시 불러올 때 승인 시각이 같으면 파일 순서대로 반영하므로 검사한 순서와 같아진다.
- 2026-10-29 (2026-11-02에 일꾼 프로세스로 바꿈) pyoxigraph에는 실행 중인 쿼리를 멈출 방법이 없다. 자연어 질의는 쿼리를 별도 스레드에서 돌리고, 20초를 넘기면 504로 답한다. 그 쿼리가 끝날 때까지는 새 질의를 받지 않는다(503). 무거운 쿼리가 겹쳐 쌓여 서버가 느려지지 않게 하기 위해서다. 쿼리가 실행되는 동안에도 다른 요청은 처리된다(직접 재 보니 쿼리가 GIL을 놓는다).

- 2026-11-05 공개 사이트 묻기 탭에 키 없는 질문 입력칸을 넣었다. 로컬 LLM이나 임베딩 모델을 받아 브라우저에서 돌리는 길도 있었지만, 그러면 모델이 쿼리를 고르거나 만들게 되어 '사람이 쓴 쿼리만 실행한다'는 원칙이 흐려지고 첫 화면 무게도 커진다. 그래서 빈칸 있는 질문 틀(`config/questions.yaml`의 forms와 slots)과 글자 조각 유사도만 쓰고, 빈칸 값의 모든 조합을 빌드 때 실행해 둔다. 받을 수 있는 거리는 100m 단위, 세대수는 100세대 단위로 정했다. 조합은 3,429가지, `ask.json`은 압축해서 약 400KB이고 입력칸을 처음 쓸 때만 받는다.
  - 빈칸 값을 넣어 문장을 만들므로, 받침에 따라 조사가 바뀌는 자리('양천로를', '화곡로66길을')를 피해 질문 문구를 고쳤다. 예: '양천로를 주소로 쓰는 건물'을 '도로명주소의 길 이름이 양천로인 건물'로, "이름에 '아파트'가 들어간 건물"을 "이름에 '아파트' 글자가 들어간 건물"로 바꿨다. 센서 질문의 '300m 안에는 없습니다'는 거리가 바뀌면 틀리므로 뺐다.
  - 이름 질문과 가양동 공동주택 질문의 층수 칸에서 0을 뺐다(`FILTER(?f > 0)`). 0은 값이 없다는 뜻이라 '0층'으로 보이면 안 된다.
