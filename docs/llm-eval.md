# LLM 평가

이 프로젝트에서 LLM이 맡은 일 두 가지(자연어 질문을 SPARQL로 바꾸기, 고시공고에서 바뀌는 내용 뽑기)를 실제 모델로 잰 결과다.
모델은 src/llm/client.py의 설정(claude-opus-5-5, 구조화 출력, 시스템 프롬프트 캐시) 그대로다.
두 평가 모두 2026-11-05에 지금 프롬프트와 그래프로 다시 쟀다. 다시 재려면:

```bash
.venv/Scripts/python -m src.eval.nl_eval
.venv/Scripts/python -m src.eval.collect_notices
.venv/Scripts/python -m src.eval.notice_eval
.venv/Scripts/python -m src.eval.report
```

## 2. 고시공고 추출 (글 -> 바뀌는 내용)

강서구청 누리집의 실제 고시(제목에 '고시'가 든 글)를 모델에 넣었다. 원문은 커밋하지 않고 번호로만 적는다
(`python -m src.eval.collect_notices`로 다시 받는다). 정답은 [eval/notice_gold.yaml](../eval/notice_gold.yaml)에 사람이 달았다.

아래 숫자는 2026-11-05에 지금 운영 프롬프트(`src.llm.notice.build_prompt`, 운영과 평가가 같은 함수)로 잰 값이다. 처음 잰 2026-10-30 뒤에 프롬프트가 두 번 바뀌었다:

## 채점을 고친 기록

결과를 처음 채점했을 때 틀린 것 5건을 하나씩 보니 모두 채점 쪽 문제여서 고쳤다. 모델을 다시 부르지 않고 저장된 결과를 다시 채점했다.

- 자연어 질의 q18(정답이 빈 결과): 정답이 비었을 때 결과가 3행까지면 맞다고 보던 규칙을, 결과도 비어야 맞다고 보도록 고쳤다. 그때 모델은 실제로 빈 결과를 내서 점수는 그대로였다 (tests/test_eval.py가 이 규칙을 지킨다). 2026-11-05 재측정에서는 거리 조건을 빼서 틀렸다.
- 고시 55402, 60941: 모델이 근거와 주소를 제목에서 가져왔는데 채점은 본문만 원문으로 봤다. 제목도 모델에 넣은 입력이므로 원문에 포함했다 (처음 점수: 근거 문장 80/82, 주소 57/58).
- 고시 68668(도로명주소 폐지): 폐지 목록이 첨부에만 있어 모델이 대상을 비웠는데, 정답은 변경을 하나 이상 요구했다. 정답 원칙(첨부에만 있는 내용은 넣지 않음)에 맞춰 이 문서의 종류 정답을 뺐다 (처음 점수: 변경 종류 8/9).
- 자연어 질의 q13, q23은 고치지 않았다. 정답이 결과에 들어 있지만 행이 너무 많아(전체 순위, 구간마다 한 줄) 엄격한 기준으로는 틀린 것으로 둔다.

## 한계

- 자연어 질의 문제 25개는 한 사람이 이 그래프를 보고 썼다. 실제 사용자의 질문 분포와 다를 수 있다.
- 고시공고 정답도 한 사람이 달았고 23건뿐이다. 정비사업 인가처럼 공간 객체가 '바뀌는' 문서인지 애매한 것은 공간 판단을 재지 않았다(null). 정답 문서가 적으므로 100%라는 값을 일반화하면 안 된다.
- 고시는 본문만 넣는다. 폐지조서 같은 첨부(엑셀, PDF)는 이 평가에 없고, 첨부표는 코드가 읽는다(src/review/address_retirement.py).
- 비용은 토큰 수로만 적는다. 단가는 Anthropic 요금표를 따른다.
